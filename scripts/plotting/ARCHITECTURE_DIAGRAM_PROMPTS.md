# FCM-MoE 框架架构图专业提示词（顶刊标准版）

> 基于Nature、IEEE、PLOS ONE等顶刊的图表设计规范，严格结合项目实际技术细节。
> 
> **核心原则**：技术严谨 + 形象表达 + 专业美观

## 一、技术参数核实（绘图前必读）

### 1.1 数据规格
| 参数 | 值 | 说明 |
|------|-----|------|
| 时间分辨率 | 15 分钟 | 每天最多96个数据点 |
| 输入特征数 F | 6 | TSI, DNI, GHI, 温度, 气压, 功率 |
| 输入窗口长度 Lx | 16 步 | = 4小时 (16×15min) |
| 预测步长 H | {4, 8, 16} | 对应 {1h, 2h, 4h} |
| 装机容量 | 50 MW | 用于nRMSE归一化 |

### 1.2 状态向量 g_t
| 参数 | 值 | 说明 |
|------|-----|------|
| 物理量数量 | 7 | TSI, DNI, GHI, Temp, Atm, Power, ΔPower |
| 统计特征 | 4 | 均值μ, 标准差σ, 最小值min, 最大值max |
| **总维度** | **28** | 7 × 4 = 28 维 |

### 1.3 PCA降维
| 参数 | 值 |
|------|-----|
| 输入维度 | 28D |
| 输出维度 | 8D |
| 保留方差 | ≈85% |

### 1.4 FCM聚类
| 参数 | 值 | 说明 |
|------|-----|------|
| 簇数 K | 3 | 三类天气工况 |
| 模糊指数 m | 2.0 | 控制隶属度软硬程度 |
| **Cluster 0** | Low Irradiance | 22.6% 样本，低辐照（黎明/黄昏/重度阴天） |
| **Cluster 1** | Clear Sky | 42.3% 样本，晴天（稳定高辐照） |
| **Cluster 2** | Cloudy/Volatile | 35.1% 样本，多云（波动性强） |

### 1.5 专家模型架构
| 参数 | 值 |
|------|-----|
| 骨干网络 | GRU（不是LSTM） |
| 层数 | 2 |
| 隐藏层维度 | 64 |
| Dropout | 0.1 |
| 输出层 | FC: 64 → H（预测步数） |

### 1.6 热启动策略
- **Global GRU** 先在全部训练数据上预训练
- 将 Global GRU 的权重**复制**到每个 Expert GRU
- 每个 Expert 在其对应簇的数据上**微调**（较小学习率）

### 1.7 路由机制
- **硬路由**：k* = argmax(μ₀, μ₁, μ₂)
- 实验证明硬路由优于软路由
- 只激活一个专家，计算效率高

## 二、形象化视觉图案设计（重点！）

> **核心理念**：每个技术模块都要有**具体的视觉图案**表达抽象概念，不只是框和线。
> 参考示例：滑动窗口模块用"真实时序曲线 + 多个半透明窗口框叠加"来形象展示"滑动"。

---

### 2.1 滑动窗口（Sliding Window）— 体现"滑动"动态感

**视觉图案设计**：
```
背景：一条真实的光伏功率时序曲线（波动的折线，约20-30个数据点）
      曲线颜色：深蓝色(#1a365d)，线宽2pt
      
叠加元素：3个半透明矩形窗口框，沿时间轴错开排列
      - 窗口1（最左）：虚线边框，填充色 rgba(0,114,178,0.1)，表示"t-2时刻"
      - 窗口2（中间）：虚线边框，填充色 rgba(0,114,178,0.2)，表示"t-1时刻"  
      - 窗口3（最右）：实线边框(2pt)，填充色 rgba(0,114,178,0.3)，表示"当前t时刻"
      
窗口框细节：
      - 每个窗口内部底部画16个小刻度线（表示16个时间步）
      - 窗口框高度覆盖曲线的波动范围
      - 三个窗口部分重叠（约30%重叠），体现"滑动"而非"跳跃"

动态感元素：
      - 窗口下方画一个水平箭头 ───▶，标注"Sliding Direction"
      - 或者在窗口框右下角画小箭头表示移动方向
      
标注：
      - 窗口框上方：X_t
      - 窗口框下方：Lx = 16 steps (4 hours)
      - 时间轴：标注 t-2, t-1, t
```

**形象隐喻**：像一个"取景框"沿着时序曲线滑动，每次框住一段历史数据

### 2.2 状态向量计算（Statistical Aggregation）— 体现"从时序提取统计量"

**视觉图案设计**：
```
左侧：一段时序曲线（与滑动窗口内的曲线相同风格）
      曲线上叠加以下可视化元素：
      
      1. 均值线(μ)：一条水平虚线穿过曲线中部，颜色#E69F00(橙色)
         标注：μ = mean
         
      2. 标准差带(σ)：以均值线为中心，上下各扩展一个σ的灰色半透明带
         填充色：rgba(150,150,150,0.2)
         标注：±σ
         
      3. 极值点标记：
         - max点：曲线最高点用红色小三角▲标记
         - min点：曲线最低点用蓝色小三角▼标记
         
      4. 多特征叠加：可以用6条不同颜色的细曲线表示6个输入特征
         （TSI深蓝、DNI浅蓝、GHI青色、Temp橙色、Atm灰色、Power黑色）

右侧：统计量汇聚成向量
      - 画7组小图标，每组包含4个符号(μ σ ▲ ▼)
      - 用多条细线从左侧曲线汇聚到右侧的一个小矩形
      - 矩形内标注：g_t (28-dim)
      
箭头：汇聚箭头，多条细线 → 一条粗线
```

**形象隐喻**：像一个"统计摘要器"，把波动的时序曲线"压缩"成几个关键统计数字

### 2.3 PCA降维（Dimensionality Reduction）— 体现"高维投影到低维"

**视觉图案设计**：
```
方案A：3D散点云投影图
      左侧：一个简化的3D坐标系，内有散乱的小点云（表示28维数据）
            点云用渐变色或多种颜色表示不同维度
            坐标轴标注：原始28维空间
            
      中间：投影光线（多条虚线从3D点云射向2D平面）
            光线颜色：浅灰色
            
      右侧：一个2D平面，上面是投影后的点（更紧凑的分布）
            平面标注：PCA 8维空间
            点用相同颜色但更集中

方案B：特征条压缩图（更简洁）
      左侧：28条细竖线并排（代表28个维度）
            每条线高度不同，颜色渐变
            标注：28D
            
      中间：漏斗形状
            宽端对准28条线，窄端输出8条线
            漏斗内标注：PCA
            漏斗边缘用虚线表示"信息筛选"
            
      右侧：8条较粗的竖线（代表8个主成分）
            颜色更鲜明，表示"浓缩的信息"
            标注：8D (85% variance)

附加元素：小饼图显示85%方差保留
      - 饼图85%填充色，15%空白
      - 标注：85% variance retained
```

**形象隐喻**：像一个"信息漏斗"，过滤掉冗余信息，保留核心特征

### 2.4 FCM聚类（Fuzzy Clustering）— 体现"模糊边界"和"软隶属度"

**视觉图案设计**：
```
核心图案：2D散点图 + 三个渐变边界的簇

散点分布：
      - 在2D平面上画约30-50个小点
      - 点按位置用不同颜色着色（渐变混合色）
      - 靠近某个簇中心的点颜色更纯，边界区域的点是混合色
      
三个簇区域：
      - Cluster 0 (蓝色#0072B2)：左下区域，椭圆形
      - Cluster 1 (橙色#E69F00)：右上区域，椭圆形  
      - Cluster 2 (灰色#999999)：中间区域，椭圆形
      
模糊边界效果（关键！）：
      - 椭圆边界不是实线，而是用**径向渐变**
      - 从中心到边缘：颜色从100%饱和度渐变到0%
      - 三个椭圆有明显重叠区域
      - 重叠区域的点用混合色（如蓝+橙=棕色调）

隶属度可视化：
      - 在图中选一个边界区域的样本点(用星号★标记)
      - 从该点引出三条线到三个簇中心
      - 线条粗细表示隶属度大小：
        * 到Cluster 1的线最粗(μ₁=0.70)
        * 到Cluster 0和2的线较细(μ₀=0.15, μ₂=0.15)
      - 或者用颜色深浅表示

簇中心标记：
      - 每个簇中心用大号×或+标记
      - 旁边标注簇名和样本比例
```

**形象隐喻**：像"热力图"，颜色越深表示归属越确定，边界区域是模糊的渐变带

### 2.5 专家模型（GRU Expert）— 体现"门控记忆"和"专门化"

**视觉图案设计**：
```
GRU单元内部结构图（简化版）：

      ┌────────────────────────────────────────┐
      │           GRU Cell (简化)              │
      │                                        │
      │    x_t ──┬──▶ [σ] ──▶ r_t (重置门)     │
      │          │                             │
      │          ├──▶ [σ] ──▶ z_t (更新门)     │
      │          │                             │
      │          └──▶ [tanh] ─┐                │
      │                       ▼                │
      │    h_{t-1} ─────────▶ ⊙ ──▶ h_t       │
      │         ↑              │               │
      │         └──────────────┘               │
      │              (循环连接)                 │
      └────────────────────────────────────────┘

门控符号：
      - [σ] 用一个小圆圈内写σ表示sigmoid激活
      - [tanh] 用小圆圈内写tanh
      - ⊙ 表示逐元素乘法（门控操作）
      - 循环箭头表示记忆传递

三个专家并排（体现专门化）：
      - 三个Expert框水平或垂直排列
      - 每个框用不同背景色（蓝/橙/灰，20%透明度）
      - 框内显示简化的GRU结构或图标
      - 框上方标注专家名称和对应天气类型
      - 框下方标注样本比例

天气图标（可选，增加形象感）：
      - Expert 0 (Low Irradiance): 日出/日落图标 🌅
      - Expert 1 (Clear Sky): 太阳图标 ☀️
      - Expert 2 (Cloudy): 云朵图标 ☁️
      （注：如果期刊不接受图标，用文字替代）
```

**形象隐喻**：像三个"专科医生"，每个专门处理一种天气类型的预测

                      │

### 2.7 硬路由（Hard Routing）— 体现"选择/开关"

**视觉图案设计**：
```
核心图案：铁路道岔 / 开关选择器

方案A：道岔形象
      
      输入隶属度：
      μ₀=0.15 ──┐
      μ₁=0.70 ──┼──▶ ◆ argmax ◆ ──┬── Expert 0 (暗淡，未选中)
      μ₂=0.15 ──┘         │       │
                          │       ├══▶ Expert 1 (高亮，选中！)
                          │       │
                          │       └── Expert 2 (暗淡，未选中)
                          │
                       k* = 1
      
      道岔符号：用菱形◆内写"argmax"
      选中路径：粗实线(3pt)，颜色高亮
      未选中路径：细虚线(1pt)，灰色

方案B：聚光灯形象
      
           ┌─────────┐
           │ μ输入   │
           │0.15     │
           │0.70 ←   │  ← 最大值高亮
           │0.15     │
           └────┬────┘
                │
                ▼
           ╱─────────╲
          ╱  聚光灯   ╲    ← 锥形光束
         ╱   (argmax)  ╲
        ╱               ╲
       ▼                 ▼
   [暗] Expert 0    [亮] Expert 1    [暗] Expert 2
                         ▲
                    被"照亮"的专家

视觉效果：
      - 被选中的Expert框：边框加粗(3pt)，背景色加深
      - 未选中的Expert框：边框变细(1pt)，背景色变淡/灰色
      - 可以用"发光"效果突出选中的Expert
```

**形象隐喻**：像"聚光灯"，只照亮一个表演者（专家），其他人在阴影中

### 3.2 模块详细规范

#### 模块A：滑动窗口输入（最左侧）
```
位置：图的左侧，占约15%宽度
形状：一个主矩形 + 1-2个虚线偏移矩形（表示滑动）

┌─ ─ ─ ─ ─ ─ ─┐  ← 虚线框（前一时刻窗口位置）
│             │
│  ┌─────────┐│  ← 实线框（当前窗口）
│  │ ~~~~~~~~││  ← 内部画简化时序曲线
│  │ X_t     ││
│  │         ││
│  │ Lx = 16 ││  ← 标注窗口长度
│  │ (4 hrs) ││
│  └─────────┘│
└─ ─ ─ ─ ─ ─ ─┘
      ─────▶     ← 下方小箭头表示"Sliding"
     Sliding

内部细节：
- 时序曲线用简单折线表示（5-7个转折点即可）
- 可在曲线上方画6个小竖线表示6个特征维度
- 窗口框内底部画16个小刻度表示16个时间步

箭头：
- 从此模块引出一条粗实线箭头 → 指向"状态向量"模块
- 同时引出另一条细实线箭头 → 直接指向"专家模型"（表示X_t也是模型输入）
```

#### 模块B：状态向量计算

位置：滑动窗口右侧

## 五、质量检查清单

绘图完成后，逐项检查：

### 技术准确性
- [ ] 输入窗口长度 = 16步（4小时）？
- [ ] 状态向量维度 = 28？
- [ ] PCA降维 = 28D → 8D？
- [ ] 簇数 K = 3？
- [ ] 专家模型是GRU（不是LSTM）？
- [ ] GRU层数 = 2，隐藏维度 = 64？
- [ ] 样本比例正确？(22.6%, 42.3%, 35.1%)

### 视觉表达
- [ ] 滑动窗口是否体现了"滑动"的动态感？
- [ ] FCM聚类是否体现了"模糊边界"？
- [ ] 热启动是否清晰表达了"知识迁移"？
- [ ] 硬路由是否体现了"只激活一个专家"？

### 排版规范
- [ ] 所有文字使用Helvetica/Arial？
- [ ] 最小字号 ≥ 5pt？
- [ ] 无阴影、无渐变、无3D效果？
- [ ] 箭头含义一致？
- [ ] 颜色符合色盲友好标准？

### 导出格式
- [ ] 导出为PDF（矢量）？
- [ ] 文字未被转为轮廓（保持可编辑）？
